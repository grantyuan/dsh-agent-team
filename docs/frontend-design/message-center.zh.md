# 消息中枢

[English](message-center.md) | 中文

收件箱回答「什么需要我」；消息中枢回答「说过什么」。它是 Human 对全部沟通记录的一次读取——可见频道里的每一个 Thread，连同发到这个人名下的、和这个人发出的每一条 Message，跨 Workspace 可检索，不必打开 Thread——并且它不做任何写入：每一行都是投影读取，页面提供的仅有普通 Human 回复路径，与它跳转进入的那个 Thread。

## 入口与面

消息中枢是与收件箱、任务并列的第三个全局面：宽侧栏 Workspace 选择行上方再添一张卡片，窄侧栏第三个图标（`IconBrowseOutlineRegular`——框在记录外的「浏览」，与收件箱队列的开口气泡相区分）。页面在场时它带 `aria-current="page"`，遵守与另两个面相同的面纪律——选中它清空 Channel/Thread 面，任何其它 Team 面收回座位，且该位置是持久导航事实，刷新后重新打开。

从消息中枢打开的 Thread 以 `messages` 为来源：返回键读作「返回消息中心」并回到中枢，保留读者离开时的 tab、筛选与滚动位置。页面不需要选中的 Workspace——它按可见 Workspace 各发一次读取，与收件箱、任务页相同。

## 一条筛选栏，两个 tab

页面骨架沿用共享会话座席——与收件箱相同的头部横带、居中栏与状态类。头部之下是一条工具栏：两个面作为一组分段 tab——「所有讨论」（topics）与「我的消息」（messages）——共用同一行筛选。搜索框、频道选择与起止时间对两个 tab 同时生效；只有方向选择（发给我的 / 我发出的）属于「我的消息」。存在任何筛选时，「清除筛选」一键还原。

输入中的关键词与已应用的关键词是两个状态：按键立即落入输入框，Host 只在停顿后被打扰一次（250ms 防抖）。筛选发给 Host，而不是在客户端重放——Host 的 `messageCenter` 搜索对主题、正文、发送者做大小写不敏感匹配并返回命中片段，读者看到的正是命中的内容。

## 读取

每个 tab 对每个可见 Workspace 各读一次 `messageCenter`，并按 Host 自己的口径合并各片——账本序号是同一个全局位置，topics 按各自最新事实排，messages 按自身序号排，都是降序，客户端不发明第二种顺序。某个 Workspace 片带 `hasMore` 时由「加载更多」续读，按各 Workspace 自己返回的 cursor 翻页；合并后重排，追加的行落在账本给它排的位置。

部分失败保留已取得的行，并在列表下方以 `role="alert"` 报告；一次一无所获且处处失败的读取保持「未到达」——呈现带重试的错误态，而不是宣称账本空无一物的空列表。Workspace 名册尚未到达时，页面停在「加载中」，不假装空态。

## 讨论行

一个讨论行是一个 Thread：参与者头像堆（Host 按首次发言顺序解析发送者，行自身不需要名册）、Thread 主题行、仅当 Thread 真在等待 Human 时的「待你决策」chip、未读胶囊，以及带绝对时间 `title` 的相对时刻。第二行在查询命中时给命中片段、否则给主题，随后是安静的事实——多少人参与、读者是否写过（「我参与过」）、Task 的在办 claim 持有人。点击一行选中其 Workspace 并打开该 Thread。

## 消息行

一个消息行陈述一条 Message：方向徽标（「发给我的」用主色，「我发出的」用发丝线）、私信带「私信」徽标、发送者名字与时刻。正文行给命中片段或裁剪后的正文；回复上下文行引用该条所答的消息——由 Host 推导（Thread 内上一条他人的消息，或 Thread 开篇），所以文案说「回复」或「讨论的第一条消息」，绝不冒充精确的回复目标。

自己发出的行带处理胶囊——「待处理」「已响应」或「已解决」——由账本事实推导（已读水位、其后的回复、认领、已收口的 Task），因此它读作对工作进度的推断，绝不是某个人的确认。Thread 行提供两个操作：「回复」打开行内输入框，「定位到讨论」跳入 Thread。私信行两者皆无：账本不为它保存 Thread，Human 也没有直发消息的通道——这一行是记录，不是门。

## 行内回复

「回复」在所答行的下方打开输入框，一次只开一个。Enter 发送，Shift+Enter 换行；输入法组词期间 Enter 归输入法。发送以 Thread 当前修订为锚——与 Thread 页相同的 `readThread` 后 `reply` 路径，顺带消化该行的未读，因为回答一条消息就是读过它。回复点名该行的对方：收到的行点名发送者，发出的行点名当初点名的成员，绝不包括读者自己。

提交成功后关闭输入框、在该行印出「回复已发出」并重读本 tab，让「我发出的」新行不必等待下一次变更唤醒；被拒绝的回复保留输入框与草稿，并在该行印出失败原因。Host 的确认迂回（点名未关注成员）会保留请求 id 与令牌，第二次 Enter 继续的是同一意图，而不是发出第二条。

## 定位

「定位到讨论」以该行的账本序号作为持久导航锚点（`focusSequence`）打开其 Thread，因此刷新会重放。Thread 页在首次读取后执行一次定位：它向前翻阅历史——有界，Host 的最大页——直到锚定事实被渲染，随即解除底部跟随，让前置的历史页不再把视口拽回末尾，把该行滚到视口中部并闪亮一次：底色与描边同时出现，不单靠颜色传达，reduced motion 下静止。定位走不到的序号——已撤回的行，或历史中不存在的序号——在时间线上方说一次，Thread 照常打开、照常可读。
