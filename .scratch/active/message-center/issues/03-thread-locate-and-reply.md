# 03 — Thread 定位与行内回复

**What to build:** 在「我的消息」里，每条消息都能就地回复，也能一键跳到它所在的 Thread 并滚动到该条消息、短暂高亮；跳转后返回键回到消息中心并保留原来的搜索与 tab。
**Blocked by:** 02
**Status:** done

- [x] 行内回复可直接发出（复用既有 reply 路径），发送后该行立即出现「我发出的」这条新消息，无需手动刷新
- [x] 点击「定位」进入 Thread，历史页以该消息为锚点加载，该消息滚入视口并高亮一次后自然消退
- [x] 定位失败（消息已被删除或 Thread 已归档）给出明确提示且不留在空白页
- [x] 从定位进入后返回，回到消息中心同一 tab、同一搜索、同一滚动位置
- [x] DM 行不提供 Thread 定位，回复走 DM 路径，界面明确区分两种回复语义
- [x] 键盘与屏幕阅读器可完成回复与定位；高亮不依赖颜色单独传达
- [x] 测试覆盖定位锚点换算、高亮一次性、返回还原、DM 与 Thread 的分流

> 取证修正（2026-10-24）：「DM 行回复走 DM 路径」的前提不成立——Host 的 `dm-sent` 写入只对 Agent 开放（`dmForAgent`），账本在 DM 两侧都拒绝 Human（ledger 注释与 `messageCenter` 投影均确认：Human 调用永远匹配不到 DM 行）。因此 DM 行按只读记录渲染（无定位、无回复按钮），上面两项按此口径勾销；未来若打开 Human DM 通道，再补行内 DM 回复。
>
> 定位锚点落为导航快照字段 `focusSequence`（与 threadRef 同生共死，刷新重放）；Thread 页定位 pass 有界（50 页 × limit 100），解除底部跟随后再 scrollIntoView，高亮一次（底色+描边，reduced motion 静止）。
